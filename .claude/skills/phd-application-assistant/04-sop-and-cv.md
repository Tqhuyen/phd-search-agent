# 04 — Statement of Purpose & CV

## Statement of purpose (SOP)

Target length: follow the program's limit (commonly 1–2 pages, sometimes 500–1000
words). If unstated, default to ~800 words.

Structure:
1. **Hook (2–3 sentences).** The specific research problem that pulls you in, tied
   to *this* lab's recent paper. Cite it.
2. **Evidence (1–2 paragraphs).** Your concrete work: problem → method → result.
   Show you can do the lab's kind of work. One paragraph per major project.
3. **Fit (1 paragraph).** Why this lab, these methods, this supervisor. Name a
   plausible project direction that extends their work and uses your strengths.
4. **Contribution & plan (1 paragraph).** What you bring (skills, datasets,
   engineering) and a rough 4-year arc if the program asks for one.
5. **Close (2–3 sentences).** Readiness, funding awareness, availability.

Rules:
- Every claim traces to `01-candidate-profile.md`. No invented results.
- Cite the PI's work by name; at least one specific paper.
- Avoid the "passionate about AI" opener. Start with the problem.
- Match the program's questions if it gives prompts; answer each explicitly.

## CV

Preferred output: LaTeX (compiles to PDF). Markdown is an acceptable fallback if
no TeX toolchain is present.

Sections, in order (reorder for relevance):
1. Header: name, email, phone, location, links (Scholar/ORCID/GitHub/site).
2. Education (reverse chronological), with thesis title and GPA/class.
3. Research experience: role, lab, dates, 2–4 bullets each. Bullet shape:
   `<action verb> <what> using <method>, <result>`.
4. Publications (peer-reviewed first, then preprints), with links.
5. Methods & skills, grouped (programming, ML, math, domain, tools).
6. Awards & funding.
7. Languages.
8. Referees (or "available on request").

Tailoring:
- Lead with the project most aligned to the lab.
- Rename the "Methods" order to surface the lab's methods first.
- Keep to the page limit; when cutting, score each bullet by (relevance to this
  posting, uniqueness, whether the SOP depends on it) and cut the lowest first —
  never cut mechanically from the oldest section.

## Always verify the PDF
Compile and inspect: page count within limit, no orphaned section titles, fonts
consistent, signature visible. If `pdftotext` is available, confirm contact
details extract as literal text.
